- Keep interface translations in a shared language context and dictionary, with document language/direction synchronized to the selected language; this keeps layout and copy consistent without resetting practice state.
- Languages: `src/i18n/index.ts` (list, RTL, weekday letters, lazy loaders). Arabic/English reference texts live in `copy` (`src/lib/i18n.tsx`); every other language is `src/i18n/locales/<code>.json` with exactly the same keys and placeholders (checked by `src/test/languages.test.ts`). A new key must be added to all 11 JSON files. Legal texts in another language: `legal/<doc>.<code>.md`, then `npm run legal` (missing → English).
- Badges (`src/lib/badges.ts`): silver = every word of a surah completed in READING, gold = in MEMORIZATION; awarded only from `completeSurah` when the surah's last word is completed. Never add timer- or accuracy-based grants. Both views report words through `RecitationContext` (`recordWords`, `finishSurah`).
- PWA: `public/sw.js` + `public/manifest.webmanifest`; the static build (`vite.capacitor.config.ts`) writes `precache.json`. Bump nothing by hand: the build stamps `sw.js` with the file-list hash.
- Word colours (green / orange / red) are saved per verse in IndexedDB (`src/lib/wordColors.ts`, store `colors` in `RecitationContext`): both views render from them and call `commitWords` at the end of a recitation; a verse's colours are replaced only when that verse is recited again — never clear them on page turns, mode toggles or verse taps. `activeRange` (the passage recited last) opens the other view at the same verses. Search: `src/lib/quranSearch.ts` + `QuranSearchModal`.
- Recitation pause / resume (`record-wav.ts` pause → `useTranscribingRecorder.pause/resume` → `useRecitation`): nothing is recorded while paused, the session (transcript, phoneme stream, word colours, position) continues on resume; stopping still ends and saves it.
- Recitation state that must survive tab switches (Mushaf view, Recite transcript, running session totals) lives in `src/context/RecitationContext.tsx`. Surah completion (stop mic, success haptic, chime): `src/lib/surahCompletion.ts`, `src/lib/chime.ts`.
- There is no AI chat. Fatwas / personal rulings are referred to qualified scholars.
- Translations + tafsir: `src/lib/quranContent.ts` (catalogue `TRANSLATIONS` / `TAFSIRS` grouped by language, sources per option, first that answers wins; cached per surah / verse in `idb`; whole editions via `downloadTranslation` / `downloadTafsir`; selector `ContentSelectModal`; choice per app language in settings `translations` / `tafsirs`). Ibn Kathir exists freely only in ar, en, ur, bn, tr, ru — every other language shows the English abridged edition with `tafsirFallbackNote`. Never add copyrighted editions (e.g. German Ilm-Verlag Ibn Kathir, German as-Sa'di) without a licence; there is no free German tafsir anywhere (Quran.com, spa5k, QuranEnc checked 11/2026), so the German header of the tafsir list shows `tafsirGermanNote`. German Rowwad translation with footnotes comes from QuranEnc (`quranEnc` source). UI: verse tap → `AyahActionMenu` (listen · translation · tafsir · mark for practice / practise range) → `TafsirModal`. Quick jump: `GoToModal` + `src/lib/goTo.ts` — surah-name autocomplete on TOP (`searchSurahs`, also by meaning), page / surah:verse below.
- "More" hub (`hub` tab, label `navHub` = المزيد, `LayoutGrid` icon, `IslamicHubView`): prayer times, Qibla, Adhkar & duas (`DuasView`: «كل الأذكار» — all 132 Hisn al-Muslim chapters from `src/data/hisnMuslim.json` (lazy-loaded; ar text + en transliteration/translation from hisnmuslim.com, Arabic references from rn0x/hisn_almuslim_json; rebuild with the scratch script idea: merge by chapter/item order) plus Quran/Sunnah duas, in categories `DUA_CATEGORIES`, search, favourites `hifz.duas.favorites.v1`, detail with counter/share/text size; the old counter view `AdhkarTab` is the «الورد اليومي» button — morning / evening / prayer / sleep / dua — `src/data/adhkar.json`, duas grouped quran / sunnah, `fromWord` starts a verse at the supplication), recording sessions (`RecordingSessionsView`: `groupBySurah` of `audioStorage.ts`, each attempt kept with `accuracy` + `mode`, up to `MAX_PER_RANGE` per range), Tajweed guide (`src/data/tajweedData.ts`), Hadith. Prayer times: `src/lib/PrayerTimesEngine.ts` — GPS → `adhan` on the device (offline); typed city → Aladhan `timingsByCity` (cached per day); offsets ±15 min; notifications `src/lib/prayerNotifications.ts` (@capacitor/local-notifications in the app, Notification API only while open on the web). Per prayer: adhan / vibrate / off (`modeOf`, saved with `setPrayerMode` BEFORE asking the notification permission — never drop the choice when permission is missing; a hint `adhanPermissionWarn` is shown instead), muezzin voice global or per prayer (`voiceOf`); voices + files in `src/data/adhanVoices.ts`, sounds in `public/adhan/` (made with `scripts/adhan-sounds.mjs`, licences in `public/adhan/CREDITS.md`; copied to Android res/raw by native-permissions.mjs, one channel per recording; iOS plays the first 30 s from Library/Sounds). Fajr always uses a recording with «الصلاة خير من النوم» (`adhanFileFor`). Settings UI: `PrayerSettingsModal`. Planning is app-wide: `src/lib/AdhanNotificationService.ts` (started in `App`, re-plans on start, settings / language change, foreground and after midnight, `PLAN_DAYS` = 7 ahead) — never tie scheduling to a screen again. Android channels: ALL voices' channels are ensured on every plan (`ensureChannels`; a missing channel makes Android drop the notification silently — the v24 Adhan bug). In-app: `announcePrayer` / `AdhanAlert` banner on any screen (web plays the Adhan without notification permission; app shows the banner on `localNotificationReceived`). Hub prayer card: `useNextPrayer` countdown. Android exact alarms: `SCHEDULE_EXACT_ALARM` + in-app prompt (`exactAlarmStatus` / `openExactAlarmSetting`); do not add `USE_EXACT_ALARM` (Play policy: alarm-clock / calendar apps only). Hadith: `src/lib/hadith.ts` (fawazahmed0/hadith-api via jsDelivr, one download per book and language, then offline search); Arabic book titles `src/data/hadithArabicTitles.ts` (the API's titles are English even in the Arabic edition).
- Reciters library (المقرئين, hub section `reciters`, `RecitersHubView`): 86 Sheikhs and all their riwayat from mp3quran.net (`src/data/recitersCatalog.json`, generated from API v3 `reciters` + `ayat_timing/reads`), favourites, live search (`searchReciters`), per-surah / whole-riwaya downloads in `src/lib/recitersHub.ts` (sequential queue, 3 attempts, stall watchdog `STALL_MS`; app: `@capacitor/file-transfer` → WebView stream appended to the file → IndexedDB; web: Cache Storage → IndexedDB; the manifest records the store), player `src/lib/hubPlayer.ts` (whole surahs, then the next one; previous / next verse by mp3quran verse timing where it exists). The shared <audio> element has one owner at a time (`claimSheikhAudio`). Go To also searches surah meanings (`src/data/surahNamesTranslated.json`, German titles after Bubenheim).
- Sheikh audio: the player lives in the screens' top row (`SheikhControls`), reads on to the end of the surah (Recite) / verse after verse through the Mushaf (`usePagePlayer`: `nextVerse` is played directly, the page only follows via `onFollow` — never make the audio chain wait for a page render) until paused; a failed verse is retried once. Lock screen via `audioPlayback.ts`: Android = the app's own BackgroundAudio plugin (`native/android/`): foreground service with an android.media.session.MediaSession (title surah, artist «بصوت الشيخ …», app icon artwork from assets, seekable progress pushed every 5 s, play / pause / previous / next / seek), PARTIAL_WAKE_LOCK + Wi-Fi lock while playing. Do NOT switch to @capgo/capacitor-media-session again (no wake lock → audio stopped with the screen off, v23–v24). iOS / web = `navigator.mediaSession`. Verse audio sources fall back everyayah → quranicaudio mirror → Quran.com CDN (`ayahUrls`). Lock-screen title «بصوت الشيخ … | سورة …» (`sessionTexts`, keys `mediaByReciter` / `mediaSurah` / `mediaAyah`), second line the verse or the riwaya. Downloads: native = CapacitorHttp + `Filesystem.writeFile` (`downloadFile` is gone since Capacitor 7), web = Cache Storage (everyayah.com allows CORS). Screen stays on via `useKeepAwake` (`src/lib/wakeLock.ts`) in the Mushaf and while reciting / listening.

- The app is serverless and local-first: no backend, no database. Persist with `src/lib/storage.ts` (kv / idb) only.
- 100 % offline AI: speech recognition runs only on the device. Default engine: Quran-Lab's streaming phoneme Zipformer (`public/models/`, NPL-1.2 — never charge for it or any feature it powers, keep `LICENSE-NPL-1.2.txt`, keep the "feedback can be wrong, not a teacher" notice). Pipeline: `audioPipeline.ts` (VAD + Kaldi fbank) → `zipformerEngine.ts` / `zipformer.worker.ts` / `zipformerCore.ts` (onnxruntime-web 1.14, WASM) → `quranAlignment.ts` (phoneme alignment, word states) → `userAdaptation.ts` (voice profile, IndexedDB `quran_user_voice_profile`). Fallback: Whisper (`whisper.ts` + `whisper.worker.ts`, @xenova/transformers) → `quranMatcher.ts`. Never send audio or text to a server, never add Groq/OpenAI/other cloud AI or API keys, never use the browser's Web Speech recognizer. `src/test/recitationAudio.test.ts` guards this. `quran_phonemes.json` is generated: `node scripts/build-phonemes.mjs`.
- The Capacitor app is built with `vite.capacitor.config.ts` (entry `src/app-main.tsx`); keep `<App />` in `src/routes/index.tsx` free of server-only code.

- Mushaf recording (v26): the page turns automatically whenever the matcher reaches the page end (`pageReadyToTurn`, or after 4 s even when little was said); a finished surah no longer switches the microphone off. Only the reader stops a recording (or the last page).
- Auto-detect the recited verse (v27, Mushaf): `src/lib/ayahLocator.ts` indexes the whole Quran (5-char shingles over the collapsed "core" stream of Zipformer phonemes or normalized Mushaf words), votes + verifies with free-start/free-end edit distance; a hit needs ≥ 85 % similarity, must be unique (repeated phrases wait) and is never the basmala alone. `MushafReader` (and the Tasmīʿ `PracticeScreen`, which switches its passage and keeps recording) look up only while the current page is not on track (`recited < 3 || accuracy < 60`), then jumps (page + start verse, `autoTurn` keeps the mic), `rec.rebaseBy(startRaw)` judges from the matched start, badge `autoDetected`.
